# CLAUDE.md — сайт направления «Агентства»

> Перед любой работой прочитай ТЗ целиком: @../Сайт направления — архитектура и план.md
> Оно — источник истины по архитектуре, схеме данных, легендам и плану итераций.

Статический сайт-просмотрщик по направлению. Данные отдельно от представления:
HTML/JS не хранят чисел, читают `data/*.json`, которые собирает `build/build.py`
из исходников в родительской папке `My work`.

## Поток данных
```
../*v6*.xlsx  ──[build/build.py]──►  data/backlog.json  ──►  HTML/CSS/JS
```
Изменился источник → `python3 build/build.py` → коммит → (позже) GitHub Pages.

## Команды
- Сборка данных: `python3 build/build.py` (нужен `openpyxl`).
- Локальный просмотр: `python3 -m http.server` → http://localhost:8000
  (через `file://` fetch JSON не работает — только http).

## Конвенции
- **id итерации**: `<тема>-<уровень2>-<#>` в ascii-slug, повтор тема==L2 схлопывается
  (напр. `zakazy-1`, `predlozheniya-2-0-214`). `#` уникален → id стабилен.
- RICE = `round(Reach*Impact*Confidence/Effort)`; Final = `round(RICE*PVMult)`.
  В xlsx это формулы без кеша — считаем в `build.py`, не берём из ячеек.
- `cardPath` = null до итерации 3 (гибрид карточек L3).

## Запреты
- Не хардкодить цифры в HTML — только через `data/*.json`.
- Не плодить метрики сверх 9 активных + 6 целевых.
- Не цитировать неподтверждённые доли (напр. 69.7% оффлайна — не baseline).

## Процесс правок (ТЗ, раздел 9)
- Правка **данных** (бэклог/цифры/тексты): меняем источник в `My work` →
  `python3 build/build.py` → коммит. HTML не трогаем.
- Правка **представления**: отдельная git-ветка под одну правку, маленькие коммиты,
  проверка локально → мерж в `main`. `main` всегда рабочая.
- Не редактировать закоммиченную итерацию «поверх» — новая правка = новое изменение в ветке.
- Перед мержем показать `git diff`: убедиться, что изменилась только нужная страница.
- Общие `assets/app.js` и `assets/style.css` — единственное «общее» место риска:
  меняешь их → проверяешь все страницы.
