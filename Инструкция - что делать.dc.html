P1ЗАКРЫТЬ ПУСТОТЫ — СНАЧАЛА
01

Построить слой L3-карточек (data/cards/ пуст)

Глубина детализации обрывается на строке бэклога: в коде cardPath ведёт в пустую папку, поэтому клик «вглубь» некуда не раскрывается.

Файлы data/cards/*.json · backlog.json (id-связь) · app.js (рендер карточки) · style.css (.b-card уже есть) Шаги
  1. Определи минимальную схему карточки: id, title, path, problem, hypothesis, evidence[], status, links[] — повтори словарь полей бэклога, чтобы не плодить новые.
  2. Сгенерируй по одному data/cards/<id>.json на каждую итерацию, у которой в backlog.json проставлен cardPath. Начни с 5–10 ключевых, не со всех 214.
  3. В app.js сними заглушку cardPath = null: подгружай json по клику (lazy fetch), рендери в существующий .b-card.
  4. Добавь дип-линк ?id=<id> для прямой ссылки на карточку (механика popstate уже в коде).
Готово когда Клик по строке с cardPath раскрывает заполненную карточку; ссылка ?id=… открывает её напрямую; пустых cardPath в данных не осталось (или они помечены «later»).
02

Положить пайплайн сборки build/ в репозиторий

README.md и CLAUDE.md ссылаются на python3 build/build.py (xlsx → data/*.json), но папки build/ в проекте нет — данные нельзя пересобрать, репозиторий несамодостаточен.

Файлы build/build.py · README.md · requirements.txt Шаги
  1. Найди скрипт (вероятно в родительской My work) и перенеси build/ внутрь репозитория сайта.
  2. Зафиксируй зависимости (openpyxl и т.п.) в requirements.txt.
  3. Пропиши в README: путь к исходному xlsx, команду запуска, какие json перезаписываются.
  4. Если скрипт держать вне репо нельзя по соображениям данных — добавь README-заметку «источник сборки: …», чтобы пустоты не выглядели потерей.
Готово когда Из чистого клона python3 build/build.py пересобирает data/*.json без ручных доустановок.
P2ЕДИНООБРАЗИЕ И ДОСТУПНОСТЬ
03

Свести словари статусов в один канон

В CSS живут шесть параллельных систем статуса: .badge, .ev-chip, .mo-badge, .rf-stat, .vbadge, .churn-type. Они говорят про близкое (готовность / достоверность / MoSCoW), но читателю приходится учить язык заново на каждой странице.

Канон уже есть: .ev-chip (комментарий «Канон чип-доказательство, ТЗ 14–18») — сделай его единственным источником статуса, остальные приведи к нему.

Файлы style.css (строки ~278–290, 821–862) · app.js (где генерятся классы) · legend.html (описать канон) Шаги
  1. Зафиксируй матрицу значений: ok / part / warn / plan / muted / closed — это и есть набор .ev-chip.
  2. Сопоставь чужие модификаторы канону: badge--ok → ev-ok, badge--review → ev-part, badge--must → ev-warn, mo-* / rf-stat → ….
  3. MoSCoW (must/should/could/wont) — это не достоверность; оставь отдельным, но тоже сведи к одному классу .prio--* вместо трёх дублей.
  4. Замени старые классы в шаблонах/рендере. Не удаляй сразу — на переходный период оставь алиасы в CSS.
  5. Опиши итоговый канон в legend.html: значение, цвет, иконка, когда использовать.
Готово когда Статус достоверности рисуется одним компонентом на всех страницах; приоритет — другим; в legend.html есть таблица «значение → вид».
04

Статус не только цветом — добавить форму/иконку

Часть бейджей различается лишь цветом рамки (ev-ok emerald vs ev-part gold). Для дальтоников это неразличимо. У .ev-chip уже есть gap:4px и inline-flex — место под значок заложено.

Файлы style.css (.ev-chip::before) · app.js (если значок в разметке) Шаги
  1. Назначь каждому значению глиф: ok ✓ · part ◐ · warn ⚠ · plan ◷ · muted ·.
  2. Добавь его через ::before на класс-модификатор — без правки разметки.
  3. Продублируй смысл в aria-label / title, чтобы скринридер читал «подтверждено», а не «галочка».
Готово когда Статус читается в чёрно-белом скриншоте; у каждого чипа есть текстовый aria-label.
05

Проверить контраст мелкого текста

--cream-dim #9FB3A4 и --muted #7E9384 на тёмном фоне в подписях 9.5–11px (.ch-xlab, .l, .sv-cnt) — у нижней границы WCAG AA.

Файлы style.css (:root токены 14–16) Шаги
  1. Прогони --cream-dim/--muted на фоне --panel #102A1F через контраст-чекер (цель ≥ 4.5:1 для мелкого).
  2. Если не проходит — подними светлоту на 1–2 ступени только для текста ≤12px (заведи --cream-dim-2), крупный не трогай.
  3. Перепроверь связки на тёмных панелях графиков (.ch-ylab/.ch-xlab fill).
Готово когда Все подписи ≤12px дают ≥4.5:1 на своём фоне (проверено чекером, а не на глаз).
06

Инлайн-цвета чипов → классы-модификаторы

В разметке встречается style="color:var(--copper)" / var(--pink) на ссылках-чипах. Не баг (токен живой), но единообразнее — модификатор. Низкий риск, делается за один проход.

Файлы *.html (now/q3/vision/rynok) · style.css Шаги
  1. Заведи .chip--copper, .chip--pink в CSS рядом с базовым .chip.
  2. Найди по проекту grep "style=\"color:var(--" и замени на класс.
  3. Зафиксируй правило в гайде: «цвет чипа — модификатором, не инлайном».
Готово когда grep по инлайн-цветам в шаблонах ничего не находит.
P3НОВЫЕ ВОЗМОЖНОСТИ
07

Память фильтров и поиска в бэклоге

Сейчас в localStorage хранится только видимость колонок (COLS_STORAGE, app.js:253/472). Активные фильтры, поиск и сортировка теряются при уходе со страницы.

Файлы app.js (рядом с COLS_STORAGE) Шаги
  1. Заведи FILTERS_STORAGE по образцу COLS_STORAGE: сохраняй {q, theme, sort, sel}.
  2. Приоритет источника: URL-параметры ?q ?theme важнее localStorage (поделились ссылкой — она побеждает).
  3. У кнопки .ctl--reset — чистить и сохранённое состояние.
Готово когда Вернулся на бэклог без параметров в URL — фильтры и поиск восстановились; ссылка с ?q перекрывает сохранённое.
08

Глобальный поиск по сайту

Поиск сейчас только внутри бэклога. Один поиск по находкам, метрикам, легендам и темам превратит сайт в «командную строку» по направлению.

Файлы app.js (хедер) · data/*.json (индекс) · style.css Шаги
  1. Собери лёгкий индекс на сборке (build/): data/search.json = [{title, page, anchor, snippet}].
  2. В хедер добавь поле + выпадашку результатов (переиспользуй стили .ctl), переход по page#anchor.
  3. Горячая клавиша / или Cmd/Ctrl-K для фокуса.
Готово когда Запрос из хедера на любой странице находит результаты со всех разделов и ведёт к нужному якорю.
09

Состояние «пусто» для data-блоков + петля «гипотеза→факт»

В CSS есть .loading и .error, но нет «пусто» (0 строк после фильтра / пустой источник). Заодно — у гипотез H-кодов есть статус, но нет фактической дельты метрики после релиза.

Файлы style.css (.empty) · app.js (рендер) · metrics.json (поле факта) Шаги
  1. Добавь класс .empty (по образцу .loading) и показывай его, когда выборка пустая — с подсказкой «сбросить фильтр».
  2. В metrics.json добавь к гипотезе поля factDelta и checkedAt; на карточке метрики покажи «план vs факт».
  3. Свяжи статус гипотезы со статус-каноном (задача 03): подтверждена / частично / опровергнута.
Готово когда Пустая выборка показывает понятное состояние, а не ломает блок; у проверенных гипотез видна фактическая дельта.
